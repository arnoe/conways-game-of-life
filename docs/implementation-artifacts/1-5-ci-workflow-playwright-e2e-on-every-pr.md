# Story 1.5 — CI workflow: Playwright E2E on every PR

## User story

As the candidate,
I want Playwright wired into CI with browser binaries installed,
So that E2E regressions cannot merge.

## Acceptance criteria

Copied verbatim from `docs/planning-artifacts/epics.md` Story 1.5 with AC-N IDs.

**AC-1.** **Given** `.github/workflows/ci.yml` has an `e2e` job, **when** a PR is opened or updated and affects `apps/web` or `apps/web-e2e`, **then** the job runs `pnpm exec playwright install --with-deps` followed by `pnpm nx e2e web-e2e` and reports a check status. **And** Playwright HTML report or trace artifacts are uploaded on failure for diagnosis.

**AC-2.** **Given** the Playwright spec passes locally, **when** CI runs the same spec, **then** the `e2e` check passes within a reasonable wall-clock time (under five minutes for the MVP spec).

> **Story-1.5 implementation note:** This story **appends a single `e2e` job to the `ci.yml` Stories 1.3 + 1.4 built**. It does NOT rewrite the workflow file. Reuse the same triggers, `concurrency` block, runner, and Node/pnpm pins.
>
> The Playwright happy-path spec itself (`apps/web-e2e/src/e2e/happy-path.spec.ts`) is **not authored in this story** — that's Story 4.1. This story configures CI to run **whatever specs already exist** in `apps/web-e2e/src/`, including the scaffold's default placeholder spec generated by `--e2eTestRunner=playwright`. AC-2's "the spec passes locally" refers to whichever spec exists at the time this story ships; the workflow is the deliverable, not the spec content.

## Locked technical decisions

These are decisions Dev does **not** need to relitigate. Defer to architecture.md / project-context.md if anything below appears ambiguous.

### Workflow file

- **Path:** `.github/workflows/ci.yml` (already exists post-Stories 1.3 + 1.4).
- **Action in this story:** **append** an `e2e` job to the existing `jobs:` map. Do not modify the existing `lint`, `typecheck`, or `test` jobs.

### Job name

Exactly `e2e`. Story 1.6's branch-protection runbook lists `e2e` as a required check by name. Do not rename to `playwright`, `e2e-tests`, etc.

### Pinned versions (must match Stories 1.3/1.4)

- Node: **20**.
- pnpm: **9**.
- Runner: `ubuntu-latest`.
- `actions/checkout@v4` with `fetch-depth: 0`.
- `actions/setup-node@v4` with `cache: pnpm`.

### Browser scope — Chromium only

- Install Playwright browsers via `pnpm exec playwright install --with-deps chromium`.
- Run E2E specs against Chromium only on CI.

The README brief calls for "at least one Playwright E2E"; the architecture §7.1 specifies one happy-path spec; the existing `apps/web-e2e/playwright.config.ts` declares Chromium, Firefox, and WebKit projects. **CI runs Chromium only** — installing all three browsers triples install time and brings no signal at this scope. Restrict the runner to the `chromium` project via `--project=chromium` (passed through Nx to Playwright). Local devs can still run all three by omitting the flag.

The `--with-deps` flag installs the OS-level libraries Playwright needs on Ubuntu (libnss, libatk, etc.). Without it, Chromium fails to launch on stock GitHub-hosted runners.

### Web server strategy — rely on `playwright.config.ts` `webServer` block

The existing `apps/web-e2e/playwright.config.ts` already has:

```ts
webServer: {
  command: 'pnpm exec nx run @cgol-scaffold/web:dev',
  url: 'http://localhost:3000',
  reuseExistingServer: true,
  cwd: workspaceRoot,
}
```

Playwright auto-starts the Next.js dev server before the spec runs and tears it down afterward. **Do not** add a separate `pnpm nx build web` step or a manual `pnpm nx start web &` background process. The `webServer` block is the single source of truth for how the app is started during E2E.

`reuseExistingServer: true` is fine on CI — there is no pre-existing server, so Playwright always starts one fresh. Locally it lets Dev iterate against an already-running `pnpm nx dev web`.

`dev` mode is acceptable for E2E in this project's scope. A production build (`pnpm nx build web && pnpm nx start web`) would be more representative of deploy but adds wall-clock cost (build + cold start) that exceeds the AC-2 5-minute budget on the cold-cache run. If the spec ever depends on production-only behavior, swap the `command` in `playwright.config.ts` — that's an edit to the config file, not to the CI workflow.

### Affected-aware filter (the AC-1 "affects `apps/web` or `apps/web-e2e`" clause)

Use `nx affected -t e2e --base=origin/main` so the `e2e` job is a no-op (zero projects) when the PR touches only docs or unrelated libs. The `e2e` target on `apps/web-e2e` declares an `implicitDependencies` on `@cgol-scaffold/web` (verified in `apps/web-e2e/package.json`), so any change to `apps/web` correctly marks `apps/web-e2e` as affected.

When `affected` resolves to zero projects, Nx exits 0. The `e2e` check still reports `success` in the PR — which is the correct behavior for a PR that doesn't touch the web surface. **Do not** add an `if:` condition on the job to skip it conditionally; let Nx's affected resolver handle the no-op cleanly. (A skipped job in GitHub Actions appears as a yellow "skipped" status, which is ambiguous against branch protection's "required check" semantics; a green `success` from a no-op `nx affected` is unambiguous.)

### Target invocation (final `run` line)

```
pnpm nx affected -t e2e --base=origin/main -- --project=chromium
```

Everything after `--` is forwarded by Nx to the Playwright runner. `--project=chromium` is the Playwright CLI flag selecting the project from `playwright.config.ts`.

### Browser cache (optional, recommended)

```yaml
- uses: actions/cache@v4
  id: playwright-cache
  with:
    path: ~/.cache/ms-playwright
    key: playwright-${{ runner.os }}-${{ hashFiles('**/pnpm-lock.yaml') }}
- run: pnpm exec playwright install --with-deps chromium
  if: steps.playwright-cache.outputs.cache-hit != 'true'
- run: pnpm exec playwright install-deps chromium
  if: steps.playwright-cache.outputs.cache-hit == 'true'
```

When cached, browsers are restored in seconds; when not, the full install runs. The OS-level deps still need re-installing on each runner (they're system-wide, not in the cache path) — `playwright install-deps` is the deps-only variant. Cache key is keyed on the lockfile so a Playwright version bump invalidates correctly.

If this caching block adds complexity Dev doesn't want to debug, skip it — the simpler `pnpm exec playwright install --with-deps chromium` on every run is fine and finishes well under the AC-2 5-minute budget. The cache is an optimization, not a correctness requirement.

### Artifact upload on failure (AC-1 "upload report or trace on failure")

```yaml
- uses: actions/upload-artifact@v4
  if: failure()
  with:
    name: playwright-report
    path: |
      apps/web-e2e/playwright-report/
      apps/web-e2e/test-results/
    retention-days: 7
```

`if: failure()` ensures artifacts only upload when the spec fails (saves storage on green runs). Upload BOTH `playwright-report/` (the HTML report) and `test-results/` (traces, screenshots, videos). 7-day retention is plenty — the PR is either merged or abandoned by then.

### CI-only environment

Set `CI=true` for the runner step that invokes the spec. GitHub Actions sets `CI=true` automatically, so no explicit env var is needed. Playwright's `forbidOnly` and conservative retry behavior key off `process.env.CI`; the existing scaffold config uses `nxE2EPreset` which respects this.

### Reference job shape (to append to `ci.yml`)

```yaml
e2e:
  name: e2e
  runs-on: ubuntu-latest
  timeout-minutes: 10
  steps:
    - uses: actions/checkout@v4
      with:
        fetch-depth: 0
    - uses: pnpm/action-setup@v4
      with:
        version: 9
    - uses: actions/setup-node@v4
      with:
        node-version: 20
        cache: pnpm
    - run: pnpm install --frozen-lockfile
    - uses: actions/cache@v4
      id: playwright-cache
      with:
        path: ~/.cache/ms-playwright
        key: playwright-${{ runner.os }}-${{ hashFiles('**/pnpm-lock.yaml') }}
    - run: pnpm exec playwright install --with-deps chromium
      if: steps.playwright-cache.outputs.cache-hit != 'true'
    - run: pnpm exec playwright install-deps chromium
      if: steps.playwright-cache.outputs.cache-hit == 'true'
    - run: pnpm nx affected -t e2e --base=origin/main -- --project=chromium
    - uses: actions/upload-artifact@v4
      if: failure()
      with:
        name: playwright-report
        path: |
          apps/web-e2e/playwright-report/
          apps/web-e2e/test-results/
        retention-days: 7
```

`timeout-minutes: 10` is a hard upper bound — AC-2 says "under five minutes for the MVP spec," and 10 minutes leaves headroom for cold-cache browser install on the first run. If the job is consistently approaching 10 min, investigate; the spec is doing too much.

## Dev notes

- **Why dev mode and not production build:** see "Web server strategy" above. If the PR feedback says "test against the prod build," swap `webServer.command` in `apps/web-e2e/playwright.config.ts`; do not edit the workflow.
- **`webServer` already configured.** Verify `apps/web-e2e/playwright.config.ts` still contains the `webServer` block with `command: 'pnpm exec nx run @cgol-scaffold/web:dev'` and `url: 'http://localhost:3000'`. If a previous PR removed or modified this block, restore it before opening the workflow PR — otherwise `pnpm nx e2e web-e2e` will hang waiting for a server that never starts.
- **First-PR self-test against the scaffold spec:** the Nx Next preset generates a placeholder happy-path spec in `apps/web-e2e/src/`. That scaffold spec should pass against the unmodified Next.js scaffold. Run `pnpm nx e2e web-e2e` locally against the current working tree before opening the workflow PR; if the scaffold spec fails locally, fix the local environment first — the workflow can't make a broken spec pass.
- **Disk space:** Chromium + deps install is ~300MB. GitHub-hosted runners have 14GB free; this is non-issue. Mentioned only because a failed install with a vague error is occasionally a disk-full red herring on self-hosted runners.
- **No flake retries on CI for now:** the existing `nxE2EPreset` config sets retries based on `process.env.CI`. Default to whatever the preset gives. **Do not** add `retries: 2` to make a flaky spec green — fix the spec instead (see project-context.md rule 19 / architecture §9 R4: assert against `>= 1`, not exact frame counts).
- **Sequencing:** this PR depends on Stories 1.3 and 1.4 having merged so the workflow file exists with `lint` + `typecheck` + `test` jobs. If 1.4 hasn't shipped yet, this story can still land — it just touches a smaller file.
- **Commit cadence:** one commit appending the `e2e` job. Optionally a second commit if Dev separates the cache block into a follow-up.

## Definition of done

- [ ] `.github/workflows/ci.yml` contains four jobs: `lint`, `typecheck`, `test`, `e2e`.
- [ ] The `e2e` job runs `pnpm exec playwright install --with-deps chromium` (or the cached-equivalent path) before invoking the spec.
- [ ] The `e2e` job invokes `pnpm nx affected -t e2e --base=origin/main -- --project=chromium`.
- [ ] The `e2e` job sets `timeout-minutes: 10`.
- [ ] Artifact-upload step uploads `apps/web-e2e/playwright-report/` and `apps/web-e2e/test-results/` on `failure()`, with 7-day retention.
- [ ] No edits to the existing `lint`, `typecheck`, or `test` jobs; no edits to workflow header/triggers/concurrency block.
- [ ] PR opened; the `e2e` check appears in the PR Checks tab alongside `lint`, `typecheck`, `test`, and reports `success` against the scaffold spec (or whichever spec exists at merge time).
- [ ] Wall-clock for the `e2e` job under 5 minutes on the warm-cache run (AC-2).
- [ ] `apps/web-e2e/playwright.config.ts` `webServer` block is unchanged from the scaffold.
- [ ] Sprint-status update is performed by the orchestrator.
